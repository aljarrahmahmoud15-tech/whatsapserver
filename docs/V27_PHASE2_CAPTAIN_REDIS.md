# V27 — المرحلة الثانية: تطبيق الكابتن وRedis/Valkey

## ما تم اعتماده

- V27 هي واجهة المالك الموحدة في مسارات `/v27` و`/admin` و`/admin.html`، مع إبقاء `admin-v26.html` للتراجع فقط.
- استبدال حرف الهوية الزخرفي بشعار `V27` في لوحة المالك وبوابة الكابتن.
- إزالة خزنة المالك من واجهة V27؛ تبقى خوادمها الخلفية للتوافق التاريخي ولا تُستدعى من الواجهة.
- تحويل بطاقات الجاهزية الأربع إلى مؤشرات صغيرة مضيئة عند النجاح، بلا إضاءة مضللة عند حالة المراجعة.

## تطبيق الكابتن

- التسجيل يدعم الاسم، الهاتف، طريقة الدخول، نوع المركبة، وموديل المركبة.
- بيانات المركبة تحفظ في `captain_invites` ثم تنتقل إلى `users` عند موافقة المالك.
- ملف الكابتن في لوحة V27 يعرض المركبة، وبطاقات الكباتن تعرضها أيضًا.
- أضيفت خدمة العملاء داخل تطبيق الكابتن عبر `/api/support/tickets` مع التصنيفات العامة والرحلات والشحن.
- أضيف زر تثبيت V27 على الجهاز عبر Web App Manifest وService Worker:
  - `/captain-manifest.json`
  - `/captain-sw.js`
- التثبيت لا يخلط بيانات التطبيق مع SQLite أو جلسة WhatsApp، ولا يضع API responses في cache الـPWA.

## Redis/Valkey

- أضيف عميل `redis` طويل العمر، يعمل فقط عند توفر `REDIS_URL`.
- عند غياب Redis أو تعطل الاتصال، يعود الخادم تلقائيًا إلى كاش الذاكرة ولا يفشل الإقلاع.
- Redis يخزن طبقة تسريع قابلة لإعادة البناء فقط:
  - `waslni:v27:prod:bootstrap:<hash>:v1` — TTL مبدئي 5 ثوانٍ.
  - `waslni:v27:prod:group-summary:<hash>:v1` — TTL مبدئي 5 ثوانٍ.
- لا تُحفظ جلسة WhatsApp، SQLite، المحافظ، قرارات الشحن، الاشتراكات، رموز QR أو أسرار المالك في Redis.
- تضاف مؤشرات الاستجابة:
  - `X-V27-Bootstrap-Cache: MEMORY-HIT | REDIS-HIT | MISS`
  - `X-Group-Summary-Cache: MEMORY-HIT | REDIS-HIT | MISS`
- أضيف `REDIS_URL` إلى `render.yaml` بصيغة `sync: false`؛ لا قيمة سرية داخل المستودع.

## الإعداد الخارجي المطلوب على Render

1. إنشاء Render Key Value/Valkey في نفس منطقة خدمة `whatsapserver-2`.
2. اختيار `allkeys-lru` وPersistence `Off` لأنه كاش قابل لإعادة البناء.
3. استخدام Internal URL فقط.
4. ربط Internal URL بمتغير `REDIS_URL` في خدمة `whatsapserver-2`.
5. قياس P50/P95 ونسبة `REDIS-HIT` قبل نقل `/status` العام إلى Redis.

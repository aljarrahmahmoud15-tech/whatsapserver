# V27 Bootstrap — المرحلة الأولى

## الهدف

تبدأ لوحة المالك V27 بقراءة موحدة وسريعة للملخص التشغيلي بدل إطلاق مجموعة طلبات التفاصيل عند فتح الصفحة.

## المسار

```http
GET /api/admin/v27/bootstrap
Authorization: Bearer <admin-token>   # أو جلسة المالك عبر cookie
```

المسار **قراءة فقط** ويعيد:

- حالة WhatsApp الأساسية دون جرد التخزين أو استدعاء WhatsApp Web.
- صحة قابلية استمرار الجلسة بصيغة آمنة.
- عدد الكباتن النشطين والمحافظ السالبة.
- أعداد الطلبات المفتوحة والمعلّقة وغير المرتبطة وعدد طلبات اليوم.
- رصيد محفظة الشركة الحالي فقط.
- عدد أعضاء القروب من آخر Snapshot مخزّن، إن وجد، دون انتظار قراءة جديدة من WhatsApp Web.

يحتوي الرد على `mutation: "none"`، ولا ينفذ أي تغيير في الجلسة أو القروب أو الرصيد أو الطلبات.

## الكاش

- كاش bootstrap داخل العملية لمدة افتراضية قدرها ثانية واحدة، قابلة للضبط عبر `V27_BOOTSTRAP_CACHE_TTL_MS`.
- ملخص القروب يحتفظ بـSnapshot قراءة فقط لمدة افتراضية قدرها 5 ثوانٍ، قابلة للضبط عبر `ADMIN_GROUP_SUMMARY_CACHE_TTL_MS`.
- القراءة المباشرة من WhatsApp Web لا تحدث أثناء bootstrap؛ تحدث فقط عند طلب ملخص القروب التفصيلي، ثم تُعاد من الكاش خلال مدة الصلاحية.

## سلوك الواجهة

1. فتح `/v27` يطلب bootstrap فقط.
2. مؤشرات الصفحة تعرض ملخص bootstrap ولا تعرض أصفارًا مصطنعة للتفاصيل غير المحملة.
3. فتح نافذة القرار التفصيلية يستدعي `ensureFullData()` مرة واحدة، ثم يحافظ على البيانات في الذاكرة.
4. زر التشخيص يعيد قراءة bootstrap السريع.
5. التحديث الكامل اليدوي وأزرار التحديث داخل النوافذ تحتفظ بسلوكها الحالي لضمان التوافق.
6. التحميل الدوري التلقائي لبيانات القروب أُزيل؛ بيانات القروب التفصيلية تُقرأ عند الطلب فقط.

## التحقق

- `node --check server.js`
- فحص صياغة JavaScript المضمّن في `public/admin-v27.html`
- `node --test test_admin_v27_bootstrap.js test_admin_v27_live_ui.js ...`
- `npm test` — جميع اختبارات المشروع ناجحة.
